# Уведомления: каналы и настройки по событиям

Профиль → вкладка «Уведомления». Пользователь подключает каналы (E-mail, Telegram, WhatsApp, MAX, ВКонтакте, Webhook, push в браузер/приложение)
и в таблице «событие × канал» выбирает, о чём и куда писать. Колокольчик на сайте работает всегда.

## Как это устроено

- `src/lib/notification-events.ts` — каталог событий, значения по умолчанию, привязка `Notification.type` → событие (`EVENT_FOR_TYPE`).
- `src/lib/notify-dispatch.ts` — диспетчер: для каждого получателя решает (`notify-decide.ts`), писать ли строку в колокольчик, слать ли Web Push и
  в какие подключённые каналы отправлять; адаптеры в `src/lib/notify-channels/*`. Внешние отправки не задерживают ответ API (fire-and-forget).
- Защита: не больше 15 сообщений в минуту на канал (остальные отбрасываются, следующее сообщение несёт пометку «ещё N не отправлено»),
  одинаковые сообщения в течение 30 с схлопываются; 3 «жёстких» сбоя подряд (бот заблокирован, номер недоступен) выключают канал
  и показывают причину в карточке; таймауты и 5xx канал не выключают.
- Тихие часы (по желанию пользователя): в окне времени доходит только колокольчик; системные сообщения проходят всегда.
- Если таблицы ещё не созданы (миграция не применена) диспетчер работает как раньше: колокольчик + Web Push.

### Значения по умолчанию (чтобы никто не потерял и не получил лишнего)

| Канал | Поведение |
|---|---|
| Колокольчик, Web Push | включены для всех событий — как было до этой функции |
| Новый канал (E-mail, Telegram, …) | пока пользователь его не подключил, ничего не меняется. После подключения личные события включены (упоминание, ответ на моё сообщение, комментарии, ЛС, новые идеи подписок, платежи, ценовые алерты), «шумные» выключены (каждое сообщение в комнатах, обсуждение платных каналов, вход в группу) |
| «Системные и безопасность» | нельзя отключить; только колокольчик и e-mail |
| Telegram | работает **без настроек сервера**: каждый пользователь подключает своего бота (см. ниже). Колонка в таблице и карточка доступны всем |
| Старый «свой бот Telegram» (`TelegramAccount`) | не затронут: пересылка платных каналов работает как раньше; блок управления им показывается в карточке Telegram только тем, у кого он уже есть. Если у пользователя тот же бот и чат подключены и в новых настройках, пост канала приходит один раз (новый путь, если событие включено в таблице) |

Новые уведомления, которых раньше не было: «Ответ на моё сообщение (цитата)» в чате (по умолчанию колокольчик + push, как «ответ на комментарий»)
и «Подписка скоро закончится» (рассылка выключена, включается переменной `SUBSCRIPTION_EXPIRY_NOTICE=1`).

## Терминал и календарь

В таблице «событие × канал» группа «Терминал и календарь» — три отдельно переключаемых события:

| Событие | `Notification.type` | Что это |
|---|---|---|
| «Достижение цены» | `price_alert` | алерт терминала `kind=price` (уровень цены) |
| «Касание линий и уровней» | `line_alert` | алерт `kind=line`: горизонтальный уровень/луч, трендовая линия, луч, продлённая линия |
| «Напоминания о событиях календаря» | `calendar_reminder` | колокольчик у события календаря |

Совместимость: старые строки колокольчика с типом `price_alert` остаются валидными. Раньше `price_alert` отвечал и за линии, поэтому пока пользователь
не задал собственный переключатель для `line_alert`, он наследует переключатели `price_alert` (`LEGACY_PREF_FALLBACK` в `notification-events.ts`).

**Алерты терминала** (`server/alert-scheduler.ts`, каждые ~15 с) выбирают тип по виду алерта. У алерта появилось поле `cooldownMin` — не чаще чем раз в N минут
для режима «каждый раз» (раньше фиксированная минута). Алерт можно поставить на горизонтальную линию, горизонтальный луч, трендовую линию, луч и продлённую линию.

**Настройки → Уведомления → «Терминал: алерты и календарь»**: значения по умолчанию для новых алертов (один раз / каждый раз и интервал, срок действия:
бессрочно/1/7/30 дней), звук и всплывающее окно в терминале при срабатывании, время напоминания календаря по умолчанию (в момент выхода / за 5 / 15 / 60 мин).
Хранятся в аккаунте вместе с остальными данными терминала (`TerminalUserData`, `kind=terminal_notify`) — новой таблицы нет. Окно создания алерта и колокольчик
календаря подставляют эти значения. Пока терминал (или страница `/calendar`) открыт, он по сокету подхватывает новые строки колокольчика этих типов и по настройкам
проигрывает сигнал / показывает окно; колокольчик на сайте в это время не пищит повторно.

**Колокольчик у события календаря** — в строках списка, в окне «день», во всплывающем окне события; в квадратах месяца отображается только состояние (мини-колокольчик).
Нажатие открывает небольшой список «когда напомнить». Вошедшему пользователю напоминание сохраняется на сервере (`CalendarReminder`, API `/api/calendar/reminders`,
до 200 активных) и приходит через диспетчер как `calendar_reminder`: колокольчик сайта, push, e-mail, Telegram и др. по настройкам — даже при закрытом браузере.
Текст: заголовок = название события, тело «Через 15 минут · США · важность высокая» и строка «на что влияет» из глоссария (для русского языка); ссылка `/calendar#<дата>`
открывает этот день. Планировщик `server/calendar-reminders.ts` (каждые 30 с) атомарно «захватывает» строку (`updateMany ... notifiedAt IS NULL`), поэтому перезапуск
или второй экземпляр не отправят дубль; строки старше 2 суток удаляются. Выключатель: `CALENDAR_REMINDERS=0`. Гостям колокольчик предлагает войти; напоминания, сохранённые
в браузере/аккаунте раньше (локальные), переносятся на сервер при первом открытии после входа.

## Что нужно сделать владельцу

После выкладки кода применить миграцию `prisma/migrations/20261004090000_notification_channels/migration.sql`
(идемпотентная; в проекте деплой делает `prisma db push` или `migrate deploy` — оба варианта подходят).
Для алертов терминала и календаря — ещё две (применять ДО выкладки кода: иначе запросы к `PriceAlert` ищут колонку `cooldownMin`):
`prisma/migrations/20261005090000_alert_cooldown/migration.sql` и `prisma/migrations/20261005091000_calendar_reminders/migration.sql`.
Без внешних аккаунтов всё уже работает для: колокольчика, Web Push, Webhook, E-mail (если задан `RESEND_API_KEY`).
Telegram работает всегда (бот пользователя). Остальные каналы в интерфейсе показывают «Не настроено администратором», пока не заданы переменные из `.env.example`.

### 1. Telegram

**Основной режим — свой бот, переменные не нужны.** Карточка Telegram ведёт по шагам: (1) @BotFather → `/newbot` → скопировать токен;
(2) вставить токен и «Проверить» (сервер вызывает `getMe` и показывает `@бот`); (3) открыть своего бота и нажать Start;
(4) «Я нажал Start» (или подождать: страница сама проверяет раз в 5 секунд) — сервер находит chat id через `getUpdates`, канал
становится подключённым и приходит тестовое сообщение. «Сменить бота» повторяет шаги 1–4.
Хранение: `NotificationChannel` (`channel='telegram'`): `address` = chat id, `label` = `@бот`, токен бота — в колонке `secret`
(открытым текстом, как и токен старого `TelegramAccount`; в API и логи не попадает, клиенту отдаётся только флаг `ownBot`).
Адаптер отправляет через токен строки, а если его нет (строка создана через бота сайта) — через `TELEGRAM_BOT_TOKEN`.
Запросы к Telegram идут только через `tgCall` (`TELEGRAM_API_BASE` / `TELEGRAM_PROXY` из окружения).

**Дополнительно — бот сайта** (необязательно; кнопка «Или через бота сайта» в карточке появляется, только если заданы
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`):

1. В Telegram откройте @BotFather → `/newbot` → имя и username (например `fomo_notify_bot`). Скопируйте токен.
2. В `/opt/fomo/.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без `@`), `TELEGRAM_WEBHOOK_SECRET` (любая длинная случайная строка).
   С российского хостинга `api.telegram.org` недоступен: уже заданные `TELEGRAM_API_BASE` / `TELEGRAM_PROXY` используются и здесь.
3. Зарегистрируйте webhook (один раз и после смены секрета): `set -a; . ./.env; set +a; npx tsx scripts/notify-setup-webhooks.ts`.
   Telegram должен достучаться до `https://fomo.spot/api/notification-settings/webhooks/telegram` (порт 443, валидный сертификат).
4. Перезапустите pm2. Пользователь жмёт «Подключить» → открывается `t.me/<бот>?start=<одноразовый токен>` → «Запустить».
   Токен хранится только хешем, живёт 30 минут и срабатывает один раз.

### 2. MAX

1. Зарегистрируйте организацию и бота на https://dev.max.ru (платформа ботов MAX), получите токен и имя бота.
2. `.env`: `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `MAX_WEBHOOK_SECRET` (случайная строка).
3. `npx tsx scripts/notify-setup-webhooks.ts` подпишет webhook (`POST /subscriptions`, события `bot_started`, `message_created`, `bot_stopped`).
4. **Не проверено на живом боте**: форма API взята из документации. Всё, что может отличаться (базовый URL, заголовок `Authorization`,
   поля `payload` / `user.user_id`), собрано в `src/lib/notify-channels/max.ts` и `src/app/api/notification-settings/webhooks/max/route.ts`.

### 3. WhatsApp (только официальный Cloud API)

1. https://developers.facebook.com → создать приложение типа Business, добавить продукт WhatsApp, привязать WhatsApp Business Account и номер
   (после верификации бизнеса в Meta). Создайте System User с постоянным токеном (права `whatsapp_business_messaging`, `whatsapp_business_management`).
2. `.env`: `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID` (ID номера из консоли, не сам номер), `WHATSAPP_TEMPLATE_CODE`, `WHATSAPP_TEMPLATE_NOTIFY`.
3. Создайте и одобрите шаблоны (WhatsApp Manager → Message templates) **на каждом из языков `ru`, `en`, `zh_CN`** с одинаковыми именами:
   - `fomo_code` — категория **Authentication**, один параметр тела `{{1}}` (код) и кнопка «Copy code». Вне 24-часового окна свободный текст
     запрещён, поэтому и код подтверждения уходит шаблоном.
   - `fomo_notify` — категория **Utility**, тело ровно с тремя параметрами, например:
     `{{1}}\n{{2}}\n{{3}}` → «Заголовок / текст / ссылка». Meta не принимает параметры с переводами строк и 4+ пробелами подряд — код сам их схлопывает.
4. Пока `WHATSAPP_*` не заданы, карточка WhatsApp показывает «Не настроено администратором», колонка в таблице скрыта.
   Входящих сообщений от пользователей сервис не обрабатывает, webhook Meta не нужен.
5. Расходы: каждое сообщение-шаблон тарифицируется Meta по категории и стране получателя.

### 4. ВКонтакте (сообщество)

1. Создайте сообщество, включите «Сообщения сообщества» и разрешите добавлять в беседы; Управление → Работа с API → ключ доступа с правом «сообщения».
2. Callback API: адрес `https://fomo.spot/api/notification-settings/webhooks/vk`, «секретный ключ» → `VK_CALLBACK_SECRET`, типы событий
   «Входящее сообщение» и «Запрет сообщений от сообщества»; строку подтверждения VK → `VK_CONFIRMATION_CODE`.
3. `.env`: `VK_GROUP_TOKEN`, `VK_COMMUNITY_NAME` (короткое имя), `VK_CALLBACK_SECRET`, `VK_CONFIRMATION_CODE`.
   Диплинк пользователя: `https://vk.me/<сообщество>?ref=<токен>`. **Не проверено на живом сообществе.**

### 5. Webhook пользователя

Ничего настраивать не нужно. Пользователь указывает HTTPS-адрес (Discord/Slack/Zapier/свой сервис), сервис шлёт подписанный JSON:
заголовки `X-Fomo-Timestamp` и `X-Fomo-Signature: sha256=HMAC_SHA256(secret, "<timestamp>.<тело>")`; в теле есть `title`, `body`, `link`, `locale`
и совместимые поля `text` (Slack) и `content` (Discord). Секрет показывается один раз при подключении.
Защита от SSRF (`src/lib/ssrf.ts`): только https, только доменное имя (не IP), порты 443/8443, домен должен резолвиться в публичные адреса
(проверка до отправки и ещё раз при соединении), редиректы не выполняются, таймаут 8 секунд.

### 6. E-mail

Использует тот же Resend, что и коды регистрации (`RESEND_API_KEY`, `EMAIL_FROM`). Адрес аккаунта подключается в один клик (он подтверждён
при регистрации); другой адрес подтверждается 6-значным кодом (15 минут, 5 попыток).

## Проверка

```
npx tsx scripts/check-notify-dispatch.ts   # решения диспетчера, умолчания, тихие часы, антиспам, учёт сбоев, локали
npx tsx scripts/check-notify-adapters.ts   # адаптеры на подменённом fetch, SSRF, подпись webhook
npx tsx scripts/check-notify-link.ts       # одноразовые токены, коды, разбор /start
npx tsx scripts/check-notify-terminal.ts   # тип уведомления по виду алерта, интервал повтора, настройки терминала по умолчанию
npx tsx scripts/check-calendar-reminders.ts # напоминания календаря: расчёт времени, выборка, захват строки, текст
```

Для просмотра интерфейса без базы данных (только dev, в production отдаёт 404): `/dev-notifications` — страница с in-memory моком API
(`?fail=1` — любое сохранение падает, чтобы увидеть откат переключателей).
